Endpoint Load Tester: Reference Manual

A lightweight, self-hosted web utility for stress testing HTTP endpoints and probing API rate limits directly from your browser's network stack and VPN connection.

GitHub Repository ↗ Read Architectural Guide

1. Architecture & Browser-Originated Load

Traditional benchmarking tools (such as k6, wrk, or autocannon) run as standalone CLI binaries on a server or developer workstation. While excellent for synthetic throughput testing, they bypass real-world client network constraints.

Endpoint Load Tester originates all HTTP traffic directly from the browser's JavaScript engine via fetch() and AbortController. This design provides three distinct engineering advantages:

  • Client-Side Routing & VPN Exit: Requests naturally originate from your actual ISP connection, corporate VPN, or mobile hotspot, accurately exercising CDN geo-routing (Cloudflare, AWS CloudFront, Fastly) and Web Application Firewall (WAF) rate limits.
  • Dual IPv4 & IPv6 Auto-Detection: Displays your active outbound IP addresses to immediately verify routing before launching tests.
  • Zero Installation Friction: Runs locally with a zero-dependency Node.js HTTP server.

2. Quick Start & Server Execution

Requirements: Node.js 18+ (no third-party dependencies).

# Clone repository
git clone https://github.com/Modracx/endpoint-load-tester.git
cd endpoint-load-tester

# Start server on default port 8787
node server.js

# Or run with custom port
PORT=9000 node server.js

Open http://localhost:8787 in any modern web browser to access the load testing dashboard.

3. Load Presets Matrix

The tool includes four pre-configured testing profiles:

Preset Requests Concurrency Pacing Primary Use Case
Burst 50 5 0 ms Peak burst capacity & queue handling.
Probe 100 2 100 ms Rate-limit boundary discovery (halts on first HTTP 429).
Paced 20 1 15,000 ms Long-duration sustained polling & keep-alive stability.
Smoke 5 1 0 ms Quick endpoint sanity check before heavy tests.

4. Real-Time Analytics & Percentile Interpretation

During and after execution, the dashboard calculates sub-millisecond latency distribution:

  • p50 (Median): 50% of requests completed within this timeframe. Represents typical user experience.
  • p90: 90th percentile response time, showing degraded requests under concurrency.
  • p99: 99th percentile response time, isolating tail-latency bottlenecks caused by database locks or cold starts.
  • Throughput: Real-time requests per second (req/s) completed.

5. CORS & Browser Connection Rules

Because tests execute within the browser security sandbox, two rules apply:

  • CORS Modes: Use cors mode if the target endpoint returns Access-Control-Allow-Origin. If testing arbitrary endpoints without CORS headers, select no-cors mode (traffic is delivered, but response body and status codes remain opaque).
  • HTTP/1.1 Socket Limits: Browsers restrict HTTP/1.1 to 6 concurrent sockets per domain. For concurrency higher than 6, ensure the target server supports HTTP/2 or HTTP/3 multiplexing.

6. Data Export & cURL Generator

Export your full benchmark run for post-incident reviews or team reports:

  • cURL Exporter: Generates exact CLI curl commands matching the active method, headers, and payload.
  • JSON / CSV Downloads: Full tabular export with timestamps, latencies, status codes, and error flags.
